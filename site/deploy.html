Deploy Foxy Vault

The vault is the server half of Foxy Switcher: it holds your Claude account tokens, refreshes them, polls usage, and hands the right one to whichever device asks. The desktop and TUI clients are agents that pair with a vault and reverse-proxy their UI through it.

Local mode (the default) runs vault and agent in the same process on your laptop. Cloud mode means the vault lives on a server you own and every device you pair shares the same account pool. This page covers the cloud path — pick the recipe that fits your hosting.

Recipes

  2. docker compose + Caddy (production)

1. Docker (one liner)

The official image is published from each GitHub Release. State (SQLite, sessions, paired devices) lives in /workspace; mount a named volume to keep it across redeploys. 

docker run -d --name foxy-vault \
  -p 8080:8080 \
  -v foxy-vault-data:/workspace \
  --restart unless-stopped \
  ghcr.io/hoveychen/foxy-switcher:latest

That binds vault on http://localhost:8080. Don't expose 8080 directly to the public internet — the vault talks plain HTTP and assumes you terminate TLS in front of it. The compose recipe below pairs it with Caddy.

2. docker compose + Caddy (production)

Two services on one host: vault on the loopback, Caddy in front terminating TLS and forwarding to it. Caddy auto-provisions a Let's Encrypt cert as long as DNS for vault.example.com points at the host.

compose.yml

services:
  vault:
    image: ghcr.io/hoveychen/foxy-switcher:latest
    restart: unless-stopped
    volumes:
      - foxy-vault-data:/workspace
    expose:
      - "8080"

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data
      - caddy-config:/config

volumes:
  foxy-vault-data:
  caddy-data:
  caddy-config:

Caddyfile

vault.example.com {
  reverse_proxy vault:8080
}

docker compose up -d brings both up. The first request triggers cert provisioning (a few seconds); after that the vault is reachable at https://vault.example.com.

Behind nginx or Traefik instead? Anything that forwards plain HTTP to vault:8080 works — the vault doesn't read X-Forwarded-* for routing decisions, so a vanilla reverse-proxy block is enough.

3. Bare metal under supervisord

On a host where Docker isn't an option, drop the linux/amd64 binary from the latest Release and run it under supervisord. State goes anywhere you like; the example uses /var/lib/foxy-switcher.

Install

sudo useradd --system --home /var/lib/foxy-switcher foxy
sudo mkdir -p /var/lib/foxy-switcher
sudo chown foxy:foxy /var/lib/foxy-switcher

curl -fsSL -o /tmp/foxy-switcher \
  https://github.com/hoveychen/foxy-switcher/releases/latest/download/foxy-switcher-linux-amd64
sudo install -m 0755 /tmp/foxy-switcher /usr/local/bin/foxy-switcher

/etc/supervisor/conf.d/foxy-switcher.conf

[program:foxy-switcher]
command=/usr/local/bin/foxy-switcher --server --mode=vault \
  --bind-host=0.0.0.0 --port=8080 \
  --data-dir=/var/lib/foxy-switcher
user=foxy
directory=/var/lib/foxy-switcher
autostart=true
autorestart=true
stdout_logfile=/var/log/foxy-switcher.log
stderr_logfile=/var/log/foxy-switcher.err.log
environment=HOME="/var/lib/foxy-switcher"

sudo supervisorctl reread && sudo supervisorctl update picks the program up. Front it with the same Caddy / nginx / Traefik config as the docker recipe — vault still wants TLS terminated upstream.

4. First-run setup & pairing

  1. Open https://vault.example.com in a browser. The vault's first-run page asks you to set an admin password. This account is what you'll log into when the desktop client asks you to approve a pairing.
  2. On the desktop client, the onboarding offers Local or Cloud vault. Pick Cloud and enter https://vault.example.com.
  3. The desktop shows a short user code and a verification URL. Open the URL in a browser, sign in to the vault, and approve the device. The desktop unlocks the moment the vault marks the pairing approved.
  4. From there, every Claude account you add through the desktop lives on the vault. Pair more devices and they all share the same pool.

5. Upgrades & backup

Docker: docker compose pull && docker compose up -d. State survives because /workspace is on a named volume.

supervisord: drop the new binary at /usr/local/bin/foxy-switcher (use install -m 0755 so the running process keeps its open file handle), then sudo supervisorctl restart foxy-switcher.

Backup: stop the vault and copy /workspace (or /var/lib/foxy-switcher) wholesale. Inside it, state.db holds accounts, sessions, and the paired-devices table; everything else is regenerable.
